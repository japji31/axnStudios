================================================================================
1. OVERVIEW — DESIGN STYLE & VISUAL DIRECTION
================================================================================
Site: "Loomsville" — an e-commerce brand selling premium farm-cotton bedding
(bedsheets, comforters) woven by artisans in India. Tagline: "Woven for Rest" /
"The elegance of comfort, in its purest form."

Design direction: warm, earthy, artisanal-luxury. Think boutique textile /
slow-living / heritage-craft aesthetic — NOT a cold tech-SaaS look. Key traits:

  - Warm neutral base (ivory/paper backgrounds, near-black charcoal text)
  - Muted, nature-derived accent palette (sage green, sand/tan, dusty rose,
    mocha brown, slate blue) evoking natural dyes and cotton fibre tones
  - Large italic serif display type (Fraunces) mixed with a clean grotesque
    sans (Karla) for body/UI — classic "editorial luxury" pairing
  - Generous whitespace, large section padding (130px desktop sections)
  - Soft, fully-rounded pill buttons and chips (border-radius: 999px)
  - Large rounded-corner cards/panels (30px radius) — soft, tactile, not sharp
  - Subtle scroll-reveal animations, slow "ease-out" easing everywhere
  - Full-bleed lifestyle photography with dark gradient overlays for hero/
    vision sections
  - Fine 1px hairline borders in low-opacity charcoal (not grey) tying every
    card/divider back to the ink colour

Two parallel visual systems coexist in the codebase:
  A) The "Loomsville brand system" — a bespoke, hand-authored CSS layer
     (custom classes: .btn, .hero, .c-card, .lv, etc.) that drives ~95% of
     what a visitor actually sees (marketing pages, shop, cart, PDP).
  B) A generic shadcn/ui + Tailwind design-token layer (--background,
     --primary, --card, etc., using OKLCH, slate-based) that powers the
     underlying shadcn component library (dialogs, dropdowns, forms, etc.)
     and the 404/error boundary screens. This is Tailwind/shadcn's default
     "new-york" slate theme, effectively unbranded/neutral.

When recreating this site, system (A), the "Loomsville brand system," is the
one that defines the actual look. System (B) should be kept as an unbranded
neutral fallback/utility layer exactly as shadcn ships it.

--- 2C. Semantic state colours -----------------------------------------------
There is NO formal design-token set for success/warning/info in the brand
system. Actual usage found in code:
  SUCCESS  → var(--sage-dark) #5F6B4E  (e.g. ".ship-msg.success", "added-note",
             checkmark bullets "✓" in .spec-bullets, success-icon circle bg)
  ERROR    → literal #b91c1c (not tokenised) — payment errors, low stock,
             remove-cart-item link
  WARNING  → not defined anywhere in the codebase
  INFO     → not defined; --slate (#6E7C87) is used decoratively but never
             as a semantic "info" colour
  DESTRUCTIVE (shadcn layer only) → oklch(0.577 0.245 27.325) ≈ #DC2626

Recommendation for recreation: keep #5F6B4E for success, #b91c1c (or a
tokenised --error: #B91C1C) for error, and introduce --warning: #C9A876
(reusing sand) if a warning state is needed, since no warning colour exists
in source.

10. ANIMATIONS & TRANSITIONS
================================================================================
Global easing curve: var(--ease) = cubic-bezier(0.16, 1, 0.3, 1) — a
"snappy-out" ease used almost everywhere for consistency.

SCROLL-REVEAL SYSTEM (two implementations coexist):
  A) `.reveal` / `.reveal.is-visible` (home page): opacity 0→1 + translateY
     28px→0 over 0.8s var(--ease), triggered via IntersectionObserver
     (threshold 0.15) with a staggered transitionDelay of (index % 4) * 90ms.
  B) `[data-stagger]` / `.in-view`, optionally `.slide-left` (translateX
     -48px→0) / `.slide-right` (translateX 48px→0) (about page): opacity
     0→1 + transform→none over 0.9s var(--ease), staggered via setTimeout
     at index*130ms once the parent `[data-reveal]` intersects (threshold 0.1).

KEYFRAME ANIMATIONS (exact):
  @keyframes drift        — hero decorative blobs float translate(30px,-24px)
                              and back, 22s ease-in-out infinite (one blob
                              delayed -9s for asynchronous motion)
  @keyframes cue / abScrollCue — scroll-cue vertical line "light pulse"
                              travels top:-100%→100%, 2.2-2.3s ease-in-out
                              infinite
  @keyframes marquee        — infinite horizontal ticker scroll,
                              translateX(0)→translateX(-50%), 26s linear
                              infinite (track duplicated ×2 for seamless loop)
  @keyframes heroImgDrift   — hero lifestyle photo subtly zooms scale(1)→
                              scale(1.06), 12s ease-in-out infinite alternate
  @keyframes abFadeUp        — about-hero text elements fade+riseIn
                              (translateY 32px→0), 1s var(--ease), staggered
                              enter delays 0.35s/0.58s/0.82s/1.3s per element

PARALLAX: About page hero image translates on scroll at 0.38x scroll speed
  (JS-driven, not CSS) via a scroll listener updating transform: translateY().

MICRO-INTERACTIONS: nav link underline width 0→100% (0.35s); icon-button
  lift + fade (0.3s); feature icon rotate(-8deg) + scale(1.06) + bg fill
  swap ivory→sage on hover (0.4s); social icon lift + sage fill (0.3s);
  color-swatch/tag lift on hover (0.3s); product image zoom-on-hover across
  nearly all card types (0.6-1.4s, slower for larger hero images = more
  luxurious/slow feel vs. quick 0.6-0.8s on grid thumbnails).
